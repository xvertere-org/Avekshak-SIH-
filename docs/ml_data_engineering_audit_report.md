### 2.2 Telemetry Ingestion & Physics Digital Twin

1. **Telemetry Ingestion Contract (`telemetry/schema.py`)**:
   - Sampling rate: Authoritative $dt = 0.1\,\text{s}$ (10 Hz).
   - Core Channels: `altitude` (m), `ambient_temp` (°C), `throttle` (%), `load` (%), `rpm` (RPM), `cht` (°C), `egt` (°C), `oil_temp` (°C), `oil_pressure` (bar), `fuel_flow` (L/h), `vibration` (g).
   - Strict metadata provenance: `source`, `source_type` (`simulated`, `synthetic`, `test_bench`, `flight_test`), `simulation_version`.
2. **Physics Digital Twin (`digital_twin/twin_model.py`)**:
   - Implements a reduced-order lumped-parameter model anchored to the Rotax 912 ULS (58 kW continuous @ 5500 RPM, 73.5 kW takeoff @ 5800 RPM).
   - **Decoupled RPM Principle**: The Digital Twin estimates expected RPM from throttle, ISA air density ratio, and aerodynamic load. Observed RPM is **never** fed back to estimate nominal states. This ensures that sensor faults (e.g., RPM sensor freeze or bias) cannot corrupt the nominal baseline.
   - Computes raw residuals: $\Delta x = x_{\text{observed}} - x_{\text{expected}}$ and normalized residuals: $r_x = \Delta x / \sigma_x$ across 7 channels (`rpm`, `cht`, `egt`, `oil_temp`, `oil_pressure`, `fuel_flow`, `vibration`).

### 2.3 ML Pipeline Implementation Status

1. **Hybrid Anomaly Detection (`anomaly_detection/pipeline.py`)**:
   - Combines four complementary detection layers:
     - Instantaneous thresholding: Normalized residual $|\tilde{r}| \ge 3.0\,\sigma$ (warning @ $1.5\,\sigma$, critical @ $4.5\,\sigma$).
     - Exponentially Weighted Moving Average (EWMA): Causal smoothing with $\alpha = 0.2$ to filter single-sample impulse noise.
     - Persistence Gating: Requires an anomaly flag to persist for $\ge 3$ consecutive timesteps ($0.3\,\text{s}$) before firing.
     - Multivariate Isolation Forest: Scikit-learn `IsolationForest(n_estimators=100, contamination=0.01)` trained on healthy normalized residuals to detect compound multi-sensor drift.
   - Output: `AnomalyStatus` (`NORMAL`, `WARNING`, `ANOMALY`, `CRITICAL`) and fused anomaly score $\in [0, 1]$.
2. **Supervised Fault Diagnosis (`fault_diagnosis/classifier.py`)**:
   - Model: `xgboost.XGBClassifier(n_estimators=200, max_depth=6, learning_rate=0.1, tree_method='hist', objective='multi:softprob')`.
   - Feature Vector (16 features):
     - 7 normalized residuals: `rpm_norm_residual`, `cht_norm_residual`, `egt_norm_residual`, `oil_temp_norm_residual`, `oil_pressure_norm_residual`, `fuel_flow_norm_residual`, `vibration_norm_residual`.
     - 3 continuous operating context: `throttle`, `altitude`, `load`.
     - 6 one-hot encoded mission phases: `phase_takeoff`, `phase_climb`, `phase_cruise`, `phase_loiter`, `phase_descent`, `phase_landing`.
   - Canonical 6-Class Taxonomy:
     1. `none` (Healthy nominal operation)
     2. `cooling_degradation` (Thermal conductance loss, CHT surge)
     3. `lubrication_degradation` (Oil pressure drop, friction heating)
     4. `fuel_injection_abnormality` (Lean/rich mixture, EGT deviation)
     5. `mechanical_degradation` (Mount stiffness degradation, high vibration)
     6. `sensor_fault` (Observation layer drift, bias, stuck, dropout)
3. **Forecasting & RUL Prognostics**:
   - **Forecasting (`forecasting/pipeline.py`)**: Google TimesFM-3 foundation model predicting a 30-step forward horizon for all 7 channels, with Causal EWMA and Persistence fallbacks.
   - **Health Index (`health_index/calculator.py`)**: Channel degradation evidence $d_i = \text{clamp}((|r_i| - 1.5) / (5.0 - 1.5), 0, 1)$, filtered by a deterministic sensor-isolation tracker (if a single sensor is anomalous while all other physical channels remain healthy, the isolated sensor is excluded from degrading the overall engine Health Index).
   - **RUL Prediction (`prognostics/pipeline.py`)**: Weakest-link EOL criteria evaluated against threshold limits ($\text{CHT} \ge 135^\circ\text{C}$, $\text{Oil Pressure} \le 1.5\,\text{bar}$, $\text{Vibration} \ge 2.0\,g$, $\text{HI} \le 0.35$). Evaluates point RUL via dual-horizon Theil-Sen robust linear regression and propagates 1000 Monte Carlo stochastic trajectories to derive P10, P50, and P90 confidence bounds.

## 3. Dataset Inspection & Technical Inventory

### 3.1 Detailed Dataset Profiles

#### 1. CWRU Bearing Data Center (`data/raw/cwru/`)
* **Source & License**: Case Western Reserve University Bearing Data Center. Open Academic Benchmark (No formal SPDX header).
* **Format & Files**: 3 MATLAB `.mat` files (v5 format), total size: 9,742,304 bytes (9.29 MB).
  - `97.mat` (3.72 MB): Normal healthy baseline (1796 RPM, 0 HP load).
  - `105.mat` (2.78 MB): Drive-end 0.007" inner race defect (1797 RPM, 0 HP load).
  - `130.mat` (2.79 MB): Drive-end 0.007" outer race defect centered (1796 RPM, 0 HP load).
* **Signals & Rates**:
  - `DE_time`: Drive-end accelerometer @ **12,000 Hz** (12 kHz).
  - `FE_time`: Fan-end accelerometer @ 12 kHz.
  - `BA_time`: Base plate accelerometer @ 12 kHz (present in 105 and 130).
  - `RPM`: 1796–1797 RPM.
  - Units: Acceleration in standard gravity ($g$).
* **Run-to-Failure & RUL**: **None**. Steady-state static load snapshots (~10 to 20 seconds duration).
* **Data Quality**: High signal-to-noise ratio, zero missing values, standard academic benchmark.

#### 2. NUST IC-Engine Journal Bearings Dataset (`data/raw/nust/`)
* **Source & License**: National University of Sciences and Technology (NUST), Islamabad. Published on Mendeley Data (v5). License: CC BY 4.0.
* **Format & Files**: 682 files, 1.19 GB total.
  - 134 `.csv` files ($\approx 250\,\text{MB}$).
  - 346 `.rtf` files and 202 `.docx` files ($\approx 940\,\text{MB}$).
  - `Engine Journal Bearings Dataset 2/` directory is an empty skeleton.
* **Signals & Columns (CSV)**:
  - 20 columns: `Time` (s), `Demand 1`, `Control 1`, `Output Drive 1`, `Channel 1`, `Channel 2`, `Channel 3` (triaxial vibration acceleration in $g$), `Channel 4` (ground ref), `Channel 1 Kurtosis` to `Channel 4 Kurtosis`, `Rear Input 1` to `Rear Input 8`.
  - Effective sampling rate: $\approx 285\,\text{Hz}$ ($dt \approx 0.0035\,\text{s}$).
  - Recording lengths: 72 rows to 9,535 rows (median 1,877 rows; 2 to 33 seconds duration).
* **Operating Conditions**:
  - Speeds: 1000 RPM, 1500 RPM, 2000 RPM.
  - Relative Humidity: 0%, 30%, 50%, 100%.
  - Ambient Temperature: $-10^\circ\text{C}$, $0^\circ\text{C}$, $15^\circ\text{C}$, $30^\circ\text{C}$, $45^\circ\text{C}$, $55^\circ\text{C}$.
  - Bearing States: Healthy vs. Faulty (journal bearing clearance wear).
* **Run-to-Failure & RUL**: **None**. Discrete operational logs under controlled environmental points.
* **Aero-Piston Relevance**: **Highest among all physical datasets**. Reciprocating IC engine with triaxial vibration and real-time kurtosis under military-standard climatic variations.

#### 3. FEMTO / PRONOSTIA Bearing Degradation Dataset (`data/raw/femto/`)
* **Source & License**: FEMTO-ST Institute / IEEE PHM 2012 Prognostic Challenge. Open Academic Challenge Benchmark.
* **Format & Files**: 24,073 files, 2.54 GB total.
  - 24,069 `.csv` files + 4 `.zip` archives.
  - 6 training bearings (`Bearing1_1` to `Bearing3_2`) + 11 test bearings (`Bearing1_3` to `Bearing3_7`).
* **Signals & Columns**:
  - `acc_XXXXX.csv`: 2,560 rows × 6 columns (Hour, Min, Sec, $\mu\text{s}$, Horizontal Accel in $g$, Vertical Accel in $g$). Sampled at **25.6 kHz** (0.1 s recording every 10 s).
  - `temp_XXXXX.csv`: 5 columns (Hour, Min, Sec, Decisec, Bearing Temp in $^\circ\text{C}$) @ 1 Hz.
* **Run-to-Failure & RUL**: **Complete ground-truth run-to-failure**.
  - Bearings run continuously from healthy baseline (RMS $\approx 0.56\,g$) to catastrophic failure (RMS $> 163\,g$, exceeding the $20\,g$ trip limit).
  - Lifespans: 7970 s to 32,690 s (2.2 to 9.1 hours).
* **Data Quality**: High fidelity; massive file fragmentation (24,000 files) requires batch preprocessing into Parquet tables.

## 6. Data Quality & Preprocessing Risks

### 6.1 Identified Risks & Mitigations

1. **Active N-C-MAPSS Download Contention (`Unconfirmed 822877.crdownload`)**:
   - *Risk*: A 9.8+ GB file is actively writing to `data/raw/cmapss/`. Moving, reading, or modifying this directory could corrupt the browser download.
   - *Mitigation*: Strictly isolate `data/raw/cmapss/` until the file is fully downloaded and renamed to its final archive name.
2. **Sampling Frequency Disparity (10 Hz vs. 64 kHz)**:
   - *Risk*: Paderborn (64 kHz), FEMTO (25.6 kHz), and CWRU (12 kHz) contain orders of magnitude higher data volume than the 10 Hz digital twin. Attempting to feed high-frequency raw arrays into the twin causes immediate memory crashes and temporal distortion.
   - *Mitigation*: High-frequency arrays must be preprocessed offline into windowed statistical aggregates (RMS, Kurtosis, Crest Factor, Band Energy) matching the 10 Hz ($dt = 0.1\,\text{s}$) telemetry clock.
3. **NUST File Redundancy & Encoding Inconsistencies**:
   - *Risk*: The 346 `.rtf` and 202 `.docx` files in NUST duplicate the data in the 134 `.csv` files and introduce proprietary Microsoft Word document formats that cannot be parsed by tabular data loaders.
   - *Mitigation*: Explicitly whitelist only `*.csv` files during NUST ingestion; ignore all `.rtf` and `.docx` files.
4. **FEMTO File Fragmentation I/O Overhead**:
   - *Risk*: 24,069 individual CSV files cause extreme filesystem seek latency and slow down training pipelines.
   - *Mitigation*: Compile each bearing's run-to-failure history into a single compressed Apache Parquet file (`data/features/femto_bearing_1_1.parquet`).
5. **Paderborn Archive Expansion Penalty**:
   - *Risk*: Expanding 32 RAR archives would consume over 30 GB of disk space.
   - *Mitigation*: Implement selective in-memory or single-file extraction using Windows `tar.exe` for representative files (`K001` normal, `KA01` outer ring, `KI04` inner ring, `KB23` combined fatigue).
