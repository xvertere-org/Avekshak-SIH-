## 1. Executive Summary

This inspection report provides an exhaustive, factual inventory and technical audit of the current workspace repository and all downloaded external datasets for the **SIH26054 Aero-Piston Engine Digital Twin** project.

### Key Inspection Highlights:
1. **Repository & Architecture Maturity**: The repository contains a fully functional, highly modular, physics-informed digital twin and PHM pipeline spanning Phases 1 through 14. All core interfaces, physics equations, anomaly detection, fault diagnosis, health index tracking, telemetry forecasting, RUL prediction, explainability (XAI), operator advisories, and an 8-page Streamlit dashboard are already implemented.
2. **Existing Telemetry Flow**: The operational system runs at an authoritative $dt = 0.1\,\text{s}$ (10 Hz) rate, processing 10 primary aero-piston telemetry channels (`rpm`, `cht`, `egt`, `oil_temp`, `oil_pressure`, `fuel_flow`, `vibration`, `altitude`, `throttle`, `load`) with physics-derived residuals generated by comparing observed values against the grey-box Rotax 912/914 digital twin.
3. **External Dataset Status**:
   - **6 datasets are verified and present locally**: CWRU Bearing (3 files, 9.29 MB), NUST IC-Engine Journal Bearing (682 files, 1.19 GB), FEMTO/PRONOSTIA Bearing Degradation (24,073 files, 2.54 GB), Paderborn University Bearing (32 RAR archives, 5.11 GB), NASA C-MAPSS Turbofan (16 files including full FD001–FD004 extractions, 11.85 MB zip, plus an active/unconfirmed ~9.2 GB download), and NASA Battery Aging (2 archives, 1.22 GB).
   - **1 dataset is absent**: BASiC (Biomisa Arducopter Sensory Critique) UAV dataset is not present (directory `data/raw/basic` contains only `.gitkeep`, 0 bytes).
4. **Physical Transferability Guardrails**: No public dataset contains a complete aero-piston engine flight telemetry stack. External datasets are component-level or methodological evidence (e.g., CWRU/Paderborn for rotational bearing fault signatures; FEMTO for accelerated run-to-failure monotonicity; C-MAPSS for multi-horizon RUL degradation curves; NUST for physical reciprocating IC-engine thermal/vibration dynamics). They must be integrated through calibrated adapters and feature extractors, never substituted directly as aero-piston telemetry.

### 4.2 NUST IC-Engine Journal-Bearing Vibration Dataset (`nust`)
* **Source & Provenance**: National University of Sciences and Technology (NUST), Islamabad, Pakistan. Published on Mendeley Data (Version 5, DOI: `10.17632/3fcrrdjjvk.5`).
* **Exact Local Path**: `d:\NIRVANAA-SIH-SUBMISSION\data\raw\nust\`
* **Total Inventory**: 682 files (1.19 GB).
  - `Engine Journal Bearings Dataset/`: 134 CSV files, 346 RTF files, 202 DOCX files.
  - `Engine Journal Bearings Dataset 2/`: 0 files (empty directory hierarchy).
* **Internal Structure & Organization**:
  The dataset is organized hierarchically by physical operating conditions:
  - Bearing State: `Healthy Bearings Dataset/` vs. `Faulty Bearings Dataset/` vs. `Additional Datasets/`
  - Engine Speeds: `1000 RPM`, `1500 RPM`, `2000 RPM`
  - Relative Humidity: `0% Humidity`, `30% Humidity`, `50% Humidity`, `100% Humidity`
  - Ambient Temperature: `-10 deg Celsius`, `0 deg Celsius`, `15 deg Celsius`, `30 deg Celsius`, `45 deg Celsius`, `55 deg Celsius`
* **Signals & Columns in CSV Files** (20 columns):
  1. `Time`: Timestamp in seconds (duration per recording varies from 2.0 s to 33.2 s).
  2. `Demand 1`: Dynamometer throttle command signal.
  3. `Control 1`: Controller drive voltage.
  4. `Output Drive 1`: Actuator output drive signal.
  5. `Channel 1`: Accelerometer Axis 1 (horizontal/radial acceleration in $g$).
  6. `Channel 2`: Accelerometer Axis 2 (vertical acceleration in $g$).
  7. `Channel 3`: Accelerometer Axis 3 (axial acceleration in $g$).
  8. `Channel 4`: Ground/reference channel ($\approx 10^{-15}$ residual voltage).
  9. `Channel 1 Kurtosis`: Real-time windowed Kurtosis metric for Channel 1.
  10. `Channel 2 Kurtosis`: Real-time windowed Kurtosis metric for Channel 2.
  11. `Channel 3 Kurtosis`: Real-time windowed Kurtosis metric for Channel 3.
  12. `Channel 4 Kurtosis`: Real-time windowed Kurtosis metric for Channel 4.
  13. `Rear Input 1` to `Rear Input 8`: Auxiliary test rig sensory inputs (digital/analog flags).
* **Sampling Rate & Data Nature**:
  - Sample count per CSV: ranges from 72 rows up to 9,535 rows (median 1,877 rows).
  - Effective sampling interval: $dt \approx 0.0035\,\text{s}$ ($\approx 285\,\text{Hz}$ logged feature rate).
  - Contains both **semi-raw vibration signals** and **precomputed statistical features (kurtosis)**.
  - RTF/DOCX files are formatted Word test measurement logs containing identical data tables and rig metadata.
* **Aero-Piston Relevance**: **Extremely High**. This is the only physical dataset in the collection derived from an **actual reciprocating Internal Combustion (IC) engine** with journal bearings inside a MIL-STD-810G environmental chamber varying temperature ($-10^\circ\text{C}$ to $+55^\circ\text{C}$) and humidity ($0\%$ to $100\%$). Ideal for calibrating environmental sensitivity and reciprocating mechanical vibration degradation.

## 7. Data Quality, Compatibility, and Architectural Findings

### 7.1 Data Quality & Integrity Findings
1. **Active Large Download in CMAPSS Directory**:
   - The file `data/raw/cmapss/Unconfirmed 822877.crdownload` is an incomplete, active browser download ($\approx 8.55\text{--}9.2+\,\text{GB}$).
   - **Finding**: This file is unfinalized, occupies substantial disk space, and should not be touched until the download completes or is terminated by the user.
2. **NUST Redundant Directory & Document Bloat**:
   - `data/raw/nust/Engine Journal Bearings Dataset 2/` is a completely empty directory tree (0 bytes).
   - `data/raw/nust/Engine Journal Bearings Dataset/` contains 346 `.rtf` and 202 `.docx` files ($\approx 850\,\text{MB}$) that duplicate the data already present in the 134 clean `.csv` files.
   - **Recommendation**: Preprocessing scripts should parse exclusively from the 134 `.csv` files and ignore the Word/RTF documents.
3. **Paderborn Compressed Format Barrier**:
   - Paderborn is distributed across 32 RAR archives ($\approx 5.11\,\text{GB}$).
   - Python's standard `zipfile` cannot unpack RAR archives. However, the system's `C:\Windows\System32\tar.exe` (libarchive) can read and extract individual `.mat` files on demand without expanding 30+ GB of uncompressed data onto the disk.
4. **FEMTO File Fragmentation**:
   - FEMTO contains 24,069 individual tiny CSV files ($\approx 2.54\,\text{GB}$).
   - Reading 24,000 separate CSV files repeatedly during training causes massive I/O overhead.
   - **Recommendation**: Preprocessing should compile each bearing run (e.g., `Bearing1_1`) into a single unified Parquet or HDF5 feature table.
5. **Sampling Frequency Disparity**:
   - Digital Twin operational pipeline runs at **10 Hz** ($dt = 0.1\,\text{s}$).
   - External raw vibration signals run at **12,000 Hz** (CWRU), **25,600 Hz** (FEMTO), and **64,000 Hz** (Paderborn).
   - **Resolution**: Raw high-frequency signals cannot be fed directly into the 10 Hz telemetry stream. They must be preprocessed into 10 Hz windowed statistical/spectral features (RMS, Peak-to-Peak, Crest Factor, Kurtosis, Band Energy).
6. **BASIC UAV Dataset Absence**:
   - `data/raw/basic/` is completely empty. The synthetic sensor fault generator (`simulator/sensor_faults.py`) currently provides calibrated sensor drift, bias, stuck, and noise models, but empirical SITL validation from BASiC cannot proceed until the dataset is acquired.
