# Phase 7 — Hybrid Anomaly Detection

## 1. Purpose & Scope

Phase 7 implements a robust, deterministic, hybrid anomaly detection layer for the SIH26054 Aero Piston Engine Digital Twin. It answers the fundamental operational question:

> **"Is the engine behaving abnormally compared with its nominal behavior?"**

### Strict Phase Boundary
Phase 7 is strictly an **anomaly detection layer**. It does **NOT** perform:
- Fault diagnosis or fault classification (e.g. diagnosing "cooling degradation" vs "oil leak").
- Component attribution.
- Fault severity estimation or RUL forecasting.
- Sensor vs physical fault root-cause determination.

Contributing channels (such as `["cht_norm_residual"]`) are exposed strictly as **signal evidence**, not diagnostic fault labels. Full fault diagnosis is strictly reserved for Phase 8.

---

## 2. Input Contract

Phase 7 consumes the normalized residuals generated by the Phase 6 Digital Twin layer encapsulated in a `ResidualFrame` or equivalent DataFrame:

### Primary Feature Channels (Normalized Residuals Only)
The detectors operate exclusively on the 7 normalized residual channels:
1. `rpm_norm_residual`: Engine speed normalized residual
2. `cht_norm_residual`: Cylinder Head Temperature normalized residual
3. `egt_norm_residual`: Exhaust Gas Temperature normalized residual
4. `oil_temp_norm_residual`: Oil Temperature normalized residual
5. `oil_pressure_norm_residual`: Oil Pressure normalized residual
6. `fuel_flow_norm_residual`: Fuel Flow normalized residual
7. `vibration_norm_residual`: Mount Vibration normalized residual

### Strict Feature Hygiene Rules
- **No Raw Channel Substitution**: If a normalized residual (e.g., `cht_norm_residual`) is missing ($NaN$), the raw physical telemetry channel (`cht`) is **never** substituted in its place.
- **NaN Preservation**: Missing values ($NaN$) are strictly preserved and never converted to $0.0$.
- **No Fault Metadata Leakage**: Labels such as `fault_type`, `fault_severity`, or mission fault schedules are completely excluded from detector inputs.

---

## 3. Architecture & Detector Roles

The hybrid architecture combines four complementary detection mechanisms with rule-based deterministic evidence fusion:

```text
ResidualFrame (Phase 6)
       │
       ▼
Residual Preprocessing & Validity Checking
 (7 primary normalized residuals; enforce min_valid_features; preserve NaNs)
       │
 ┌─────┴───────────────────────────────────────────────────────┐
 │                                                             │
 ▼                                                             ▼
1. Residual Threshold Detector (Instantaneous)        4. Isolation Forest (Multivariate)
 (Per-channel warning, anomaly, & critical bounds)     (Fitted exclusively on healthy ResidualFrame)
       │                                                       │
       ▼                                                       │
2. EWMA Temporal Detector (Smoothed)                           │
 (Per-channel EWMA, configurable alpha & bounds)               │
       │                                                       │
       ▼                                                       │
3. Persistence Gate (Sustained check)                          │
 (N consecutive abnormal samples required;                     │
  ignores missing/insufficient data)                           │
 │                                                             │
 └─────────────────────────────┬───────────────────────────────┘
                               │
                               ▼
                    Deterministic Evidence Fusion
    (Immediate critical override + Persistence/EWMA/Threshold/IF Fusion)
                               │
                               ▼
                         AnomalyFrame
```

### 1. Residual Threshold Detector (Instantaneous)
- **Role**: Detects large instantaneous departures from nominal expectations on normalized residuals.
- **Configurable Parameters**:
  - `warning_threshold`: Default `1.5` $\sigma$
  - `anomaly_threshold`: Default `3.0` $\sigma$
  - `critical_threshold`: Default `4.5` $\sigma$ (triggers immediate critical override)
  - `channel_thresholds`: Optional per-channel overrides.
- Exposes instantaneous score $\in [0.0, 1.0]$ and crossing channel lists.

### 2. EWMA Temporal Detector (Smoothed)
- **Role**: Smooths high-frequency sensor and model noise, captures sustained directional drift, and suppresses isolated transient glitches.
- **Filter Update**:
  $$z_{t, ch} = \alpha x_{t, ch} + (1 - \alpha) z_{t-1, ch}$$
- **Configurable Parameters**:
  - `alpha`: Smoothing factor (default `0.2`).
  - `warning_threshold`: Default `1.2`
  - `anomaly_threshold`: Default `2.2`
- If $x_{t, ch}$ is $NaN$, prior state is maintained; $NaN$ is never imputed as zero.

### 3. Persistence Gate
- **Role**: Distinguishes transient noise spikes from genuine sustained anomalies.
- **Input Condition**: Evaluates whether current instantaneous or EWMA evidence indicates abnormal deviation.
- **Counting Rules**:
  - Increments on consecutive abnormal samples.
  - Resets to `0` when signal returns to normal.
  - Does **NOT** increment on missing samples or `INSUFFICIENT_DATA` rows.
  - Does **NOT** increment on sub-abnormal elevated residuals.
- **Threshold**: Requires `min_consecutive` samples (default `3`) to satisfy persistence.

### 4. Isolation Forest Detector (Multivariate)
- **Role**: Captures subtle cross-channel multivariate correlations and multi-sensor deviations that univariate detectors might miss.
- **Training Constraint**: Fitted **strictly** on healthy baseline residual telemetry (`fault_type == 'none'`). Fault-injected data is never used during training.
- **Determinism**: Fixed `random_state` (default `42`) ensures 100% deterministic trees.
- **Deterministic Score Mapping**:
  Maps raw `decision_function(X)` to $[0.0, 1.0]$ via calibrated sigmoid:
  $$s_{\text{iso}} = \frac{1}{1 + \exp(12.0 \cdot df)}$$
  - $s \approx 0.0$: Deep inlier (nominal)
  - $s = 0.5$: Decision boundary ($df = 0$, warning)
  - $s \ge 0.7$: Deep outlier (anomaly)

---

## 4. Validity Handling & Minimum-Valid-Feature Rule

- **Threshold**: Configurable `min_valid_features` (default `4` of `7` normalized residual channels).
- **Behavior**:
  - If valid (finite non-null) feature count $< \text{min\_valid\_features}$:
    - `anomaly_status` is deterministically set to `INSUFFICIENT_DATA`.
    - `anomaly_score` evaluates to `NaN`.
    - `contributing_channels` is empty.
  - **CRITICAL INVARIANT**: `INSUFFICIENT_DATA` is **NEVER** silently converted to `NORMAL`.

---

## 5. Evidence Fusion Logic

The `EvidenceFusionEngine` executes a deterministic decision tree:

1. **Rule 1 (Quality Guard)**:
   If row fails `min_valid_features` $\to$ `INSUFFICIENT_DATA`.
2. **Rule 2 (Immediate Critical Override)**:
   If instantaneous residual $\ge \text{critical\_threshold}$ (e.g. $\ge 4.5$) $\to$ `ANOMALY` immediately (prevents dangerous delay for catastrophic spikes).
3. **Rule 3 (Sustained Anomaly via Persistence)**:
   If `persistence_satisfied` **AND** (EWMA anomaly, threshold anomaly, or Isolation Forest anomaly) $\to$ `ANOMALY`.
4. **Rule 4 (Warning / Transient Spike)**:
   If threshold warning, EWMA warning, Isolation Forest warning, or unpersisted anomaly spike $\to$ `WARNING`.
5. **Rule 5 (Nominal)**:
   Otherwise $\to$ `NORMAL`.

### Continuous Anomaly Score
Fused continuous score $s \in [0.0, 1.0]$ is computed as a weighted combination of threshold, EWMA, persistence, and Isolation Forest scores:
$$s = w_{\text{thresh}} s_{\text{thresh}} + w_{\text{ewma}} s_{\text{ewma}} + w_{\text{persist}} s_{\text{persist}} + w_{\text{iso}} s_{\text{iso}}$$
- Bounded to $[0.75, 1.0]$ if status is `ANOMALY`.
- Bounded to $[0.35, 0.74]$ if status is `WARNING`.
- Bounded to $[0.0, 0.34]$ if status is `NORMAL`.

---

## 6. Output Contract: `AnomalyFrame`

Each evaluated sample produces an `AnomalyRecord` containing:
- Provenance: `timestamp`, `engine_id`, `mission_id`, `mission_phase`, `source`, `source_type`.
- Primary Results: `anomaly_score`, `anomaly_status` (`NORMAL`, `WARNING`, `ANOMALY`, `INSUFFICIENT_DATA`).
- Detector Sub-scores: `threshold_score`, `ewma_score`, `persistence_score`, `isolation_score`.
- Diagnostic Evidence: `persistence_count`, `contributing_channels` (e.g. `["cht_norm_residual"]`).
- Quality Context: `quality_status`, `missing_features`.

Wrapped in an `AnomalyFrame` container providing:
- `.to_dataframe()`: Full pandas DataFrame export.
- `.to_records()`: List of dictionaries.
- `.anomalies()`: Filtered subset of `ANOMALY` samples.
- `.warnings()`: Filtered subset of `WARNING` samples.
- `.normal()`: Filtered subset of `NORMAL` samples.
- `.insufficient_data()`: Filtered subset of `INSUFFICIENT_DATA` samples.
- `.summary()`: Tabular status distribution and anomaly rate.

## 7. Operational Limitations & Fusion Rationale

1. **Steady-State Baseline Calibration**:
   The baseline Isolation Forest and EWMA detectors are calibrated on steady-state flight operation (e.g. cruise). Extreme flight transitions (such as takeoff thrust transients) should be evaluated against flight-phase-specific thresholds or baseline models.
2. **Missing Feature Imputation**:
   When a row meets the minimum feature threshold ($4/7$) but is missing $1$ or $2$ channels, the Isolation Forest uses healthy baseline training medians to evaluate multivariate path length, rather than zero.
3. **Multivariate Fusion Rationale (WARNING → Persistence Confirmation → ANOMALY)**:
   When multiple normalized residual channels are simultaneously elevated below the critical $4.5\,\sigma$ threshold (e.g. at $2.0 - 2.5\,\sigma$), the Isolation Forest detects this multivariate correlation. The fusion engine deliberately outputs `WARNING` on the initial transient samples before latching `ANOMALY` upon reaching `persistence_min_consecutive = 3`.
   - **Rationale**: An isolated, 1-sample multi-channel disturbance (e.g., bus electromagnetic interference or sensor bus supply jitter lasting $\le 0.5$ s) is safely alerted as a `WARNING` without causing an immediate, premature system shutdown or false sustained alert.
   - Once the anomaly persists across consecutive samples ($1.5$ s at $2\text{ Hz}$), persistence confirms the condition to `ANOMALY`.
   - Single-channel catastrophic excursions ($\ge 4.5\,\sigma$, e.g. severe overspeed or sudden loss of oil pressure) bypass persistence immediately via Rule 2 to protect engine integrity.

## 8. Validation Taxonomy & Real-World Generalization Boundary

Phase 7 strictly enforces a three-level taxonomy regarding validation claims:

### Level A: Synthetic Aero-Piston Simulator Validation (Current Validated Scope)
- **Scope**: Calibrated grey-box aero-piston physics simulator telemetry across standard MALE-UAV profiles (climb, cruise, loiter, descent).
- **Evaluation**: Validated on healthy baseline telemetry (predominantly `NORMAL`, low false alarm rate) and known fault-injected scenarios (cooling degradation, lubrication leak, fuel injection abnormality, mechanical vibration unbalance, and sensor bias/drift).
- **Status**: **Fully verified and passing 195/195 tests.**

### Level B: External Public Benchmark Validation (Methodology Only)
- **Scope**: Heterogeneous public benchmark datasets (e.g., CWRU bearing dataset, Paderborn vibration dataset, FEMTO/PRONOSTIA bearing run-to-failure, NASA C-MAPSS turbofan).
- **Usage Boundary**: These datasets serve **strictly as algorithmic methodology and transfer benchmark evidence**. They are **NOT** aero-piston engine telemetry, are **never** merged into the aero-piston training baselines, and maintain distinct provenance.

### Level C: Real MALE-UAV Engine Generalization Boundary (Open Operational Milestone)
- **Scope**: Certified OEM flight data, ground test bench runs on physical piston engines, or instrumented test-cell telemetry.
- **Explicit Boundary**: Current Phase 7 results **do NOT establish real-world MALE-UAV flight-data generalization**. Demonstrating generalization to real flight data is an operational milestone that requires actual instrumented flight telemetry and sensor noise profiles. No claim of real-flight validation is made.
